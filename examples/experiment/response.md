# 实验设计：SFT 的 loss mask 会不会影响结果？

先说我做的假设：你说的 SFT 是 decoder-only 语言模型的监督微调；笔记本是普通 CPU（有 Python，numpy 可用，torch 可以自己装）；你愿意花几十分钟到两三小时；"影响结果"指留出集上回答部分的质量，而不只是训练 loss。

## 先请你写一两句预测（再往下看）

"只对回答算 loss"和"全部 token 都算 loss"，你觉得留出集上的回答质量谁更好、差多少？你觉得它取决于什么（数据量？prompt 和回答的长度比？）？写完再看下面。这样结果出来时你才知道自己的直觉对不对。

## 先把问题拆开：这里藏着一个混淆变量

"算不算 prompt 的 loss"表面上是一个开关，实际上常常同时改了两件事：

1. 梯度里多了 prompt token 的项（想测的东西）。
2. 如果按"所有 token 取平均"归一化，回答 token 的权重被稀释了（prompt 越长稀释越多），等价于回答部分的有效学习率变小（想测之外的东西）。

所以不要做 0/1 比较，做一个旋钮：

```
loss = ( Σ_回答token nll  +  λ · Σ_prompt token nll ) / 回答token数
λ = 0   -> loss mask（基线）
λ = 1   -> 全部 token 都算
0<λ<1   -> 中间剂量
```

每个臂都除以"回答 token 数"，回答部分的梯度尺度完全一样，唯一变的就是 λ。这样得到的是一条剂量曲线，比一对点更能说明因果。

补充一点（推导，前提是用 Adam 且不裁剪梯度）：Adam 的更新对整体 loss 缩放近似不变，所以"归一化口径"的差别在 Adam 下影响较小；用 SGD 或开了梯度裁剪时则不然。因此实验里要写明优化器和裁剪设置。

## 实验计划

| 项 | 内容 |
|---|---|
| **问题** | 在 prompt 上加 loss，对留出集回答质量的影响，随 λ、数据量、prompt/回答长度比怎么变？ |
| **假设（可证伪）** | 当 prompt 里"不可预测的信息"很多（长、随机、与回答无关的内容）且训练预算有限时，λ 越大，留出集回答质量越差；当 prompt 短、回答长、数据少时，这个差异小到测不出，甚至 λ>0 略有帮助。 |
| **基线** | λ=0（标准 loss mask） |
| **唯一改变的变量** | λ ∈ {0, 0.1, 0.3, 1}。第二层再扫一个次要变量：prompt 长度/回答长度之比 |
| **保持不变** | 同一份数据与顺序、模型与初始化、优化器与学习率、步数、batch、评估集、"回答 token 数"归一化 |
| **种子** | 至少 3 个，报均值和波动 |
| **指标** | 主指标：留出集回答 token 的 NLL 与准确率/exact match。诊断指标：训练集回答 NLL（看过拟合）、留出集 prompt NLL（看 prompt 建模能力是否被保留或破坏）、各步到达某准确率的步数（看学习速度） |
| **失败判据** | 如果各 λ 的留出集回答指标差异小于种子间波动，就不能说 loss mask 有影响；如果 λ 越大反而越好，假设被推翻 |
| **成本** | 第一档：numpy 玩具模型，约 15 分钟，无需 GPU。第二档：小真模型，见下 |
| **不能说明什么** | 玩具实验不能说明大模型、真实指令数据、RLHF 前后的结论；任何一档都只回答"在这个设置下"。 |

我对结果可能意味着什么的读法：

| 现象 | 可能说明 |
|---|---|
| λ 越大回答越差，且训练回答 loss 也更高 | prompt 梯度占用优化预算或容量（干扰）。要再加长训练步数，确认是"学得慢"还是"最终就差" |
| λ 越大回答越差，但训练回答 loss 很低 | 过拟合：模型在记 prompt |
| 各 λ 无差异 | 在这个规模下 loss mask 不重要 |
| λ>0 更好 | prompt loss 起到辅助正则/表示学习的作用 |
| 留出集 prompt NLL：λ=0 明显高于 λ>0 | loss mask 让模型"不再会建模 prompt"，这是副作用，不一定影响回答 |

## 第一档：笔记本上能跑完的玩具实验（我已经跑了）

任务：prompt 是 8 个随机 token（不可预测，熵为 log V），回答是其中几位按位置相加取模。一个手写反向传播的小 MLP 语言模型，用 Adam。脚本是纯 numpy：`lossmask_toy.py`，同目录下的 `results.txt` 是我这次的原始输出。

**结果（Checked，仅限这个玩具；5 个种子，6000 步，学习率 3e-3，V=8，隐层 64）**

数据量 n=500：

| λ | 留出集回答准确率 | 留出集回答 NLL | 训练集回答 NLL |
|---|---|---|---|
| 0 | 0.154±0.004 | 7.58 | 0.001 |
| 0.1 | 0.142±0.003 | 8.42 | 0.010 |
| 0.3 | 0.135±0.006 | 9.09 | 0.015 |
| 1 | 0.129±0.004 | 9.13 | 0.033 |

随机猜的准确率是 0.125。这一档所有臂都在背训练集，留出集接近随机，**不构成对 loss mask 的有效比较**，只是告诉我们这个量级的数据下任务学不出来。

数据量 n=5000：

| λ | 留出集回答准确率 | 留出集回答 NLL | 留出集 prompt NLL |
|---|---|---|---|
| 0 | 0.445±0.148 | 1.16 | 2.80 |
| 0.1 | 0.347±0.164 | 1.46 | 2.12 |
| 0.3 | 0.260±0.126 | 1.60 | 2.10 |
| 1 | 0.127±0.005 | 2.09 | 2.08 |

prompt NLL 的理论下限是 log 8 = 2.079。

**怎么读（保守地）**

- 在这个玩具和这个预算里，λ 越大，6000 步后的回答越差；λ=1 时几乎没开始学（0.127 ≈ 随机）。方向和我设计的假设一致，但 λ=0 的种子间波动很大（±0.148），0 与 0.1 的差距在波动范围内，只有 λ=0 对 λ=1 的差距明显。
- 这些模型都没收敛，所以这只能说明**学习速度被拖慢**，不能说明最终性能更差。要区分这两件事，必须延长训练再看，我没有做。
- 副作用得到确认：λ=0 的模型留出集 prompt NLL 是 2.80，高于下限 2.08，它不会再建模 prompt，λ>0 则回到下限附近。
- 一个可能的机制（猜想，未测）：随机 prompt 的 8 个位置产生的是纯噪声梯度，和回答的 3 个位置共享参数，Adam 按参数归一化后信噪比被压低。要验证可以单独记录两部分梯度的范数与夹角。
- 另外还有一个我没排除的问题：玩具任务偏难，λ=0 也只学到 0.445，所以"λ 越大越差"有可能部分来自任务边缘可学性。换更简单或更难的任务看趋势是否保持，是下一步。

## 第二档：真实小模型（需要你自己跑，我没有跑，代码未测）

- 模型：约 100M 量级的小模型（例如 SmolLM 135M 或 Pythia 70M 一类，具体型号和下载大小请你自己确认），CPU 上全参数微调，序列长度 128，batch 8，几百步。每步耗时我没测过，先跑 20 步估算再定总步数。
- 数据：构造两份结构相反的数据，直接对应假设里的"prompt 长度/回答长度之比"。A：长 prompt、短回答（抽取式问答、分类）。B：短 prompt、长回答（开放式指令）。每份约 2000 条，留出 300 条。
- 实现 λ（PyTorch，代码未测）：

```python
# logits: (B,T,V) 已对齐到下一个 token；is_answer: (B,T) bool；pad_mask: (B,T) bool
nll = F.cross_entropy(logits.transpose(1,2), labels, reduction="none")   # (B,T)
w = torch.where(is_answer, 1.0, lam) * pad_mask
loss = (nll * w).sum() / (is_answer & pad_mask).sum()                    # 除以回答 token 数
```

- 评估：留出集回答 NLL，加一个任务相关的准确率；另外读几条生成，看有没有"回答完继续编下一个用户问题"这类行为（EOS 是否也算在回答里要统一）。
- 3 个种子 × 4 个 λ × 2 份数据 = 24 次运行，先砍到 λ∈{0,1}、1 个种子试通流程，再补全。
